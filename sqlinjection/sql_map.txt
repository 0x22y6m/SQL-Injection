Room : SQL MAP

sqlmap is an open source penetration testing tool ,that automates the process of detecting and exploiting SQL injection flaws and taking over database servers.

Basic commands:

Options                             Description
-u URL, --url=URL                   Target URL (e.g."https://www.site.com?vlun.php?id='1'")
--data=DATA                         Data string to be sent through POST (e.g. "id=1")
--random-agent                      use randomly selected HTTP user-Agent header value
-p TESTPARAMETER                    Testable parameter(s)
--level=LEVEL                       Level of tests to perfrom (1-5,default 1)
--risk=RISK                         Risk of tests to perfrom (1-3,deafult 1)

Enumeration commands:
These options can be used to enumerate the back-end database management system information, structure,and data contained in tables.

Options                            Description
-a -all                            Retrieve everything
-b, --banner                       Retrieve DBMS banner
--current-user                     Retrieve DBMS current user
--current-db                       Retrieve DBMS current database
-p username                        username parameter for the attack
--passwords                        Enumerate DBMS users password hashes
--dbs                              Enumerate DBMS databases
--tables                           Enumerate DBMS database tables
--columns                          Enumerate DBMS database table columns
--schema                           Enumerate DBMS schema
--dump                             Dump DBMS database table entries
--dump-all                         Dump all DBMS databases tables entries
--is-dba                           Detect if the DBMS current user is DBA
-D <DB NAME>                       DBMS database to enumerate
-T <TABLE NAME>                    DBMS database table(s) to enumerate
-C COL                             DBMS database table column(s) to enumerate
--sql-shell                        will give an interactive SQL shell prompt
--dbms=<DBMS name>                will only enumerate only mentined databases

Operating System access commands
These options can be used to access the back-end database management system on the target operating system.

Options                           Description
--os-shell                            Prompt for an interactive operating system shell
--os-pwn                                Prompt for an OOB shell, Meterpreter or VNC
--os-cmd=OSCMD                    Execute an operating system command
--priv-esc                            Database process user privilege escalation
--os-smbrelay                       One-click prompt for an OOB shell, Meterpreter or VNC

Note that the tables shown above aren't all the possible switches to use with sqlmap. For a more extensive list of options, run sqlmap -hh to display the advanced help message.

--batch 
allowing the tool to run without requiring default user input
and also select the default values (no need our input)


--threads (1-10)
option in sqlmap specifies the maximum number of concurrent HTTP(S) requests to perform, with a default value of 1 and a maximum limit of 10.


--risk (1-3)
option controls the intrusiveness and potential destructiveness of the SQL injection payloads used during a scan, ranging from 1 to 3. 
Risk 1 (Default): Uses mostly harmless payloads, such as basic boolean-based and error-based injections, which are generally safe for the target database. 
Risk 2: Adds heavy time-based blind injection tests, which can significantly load the database server and slow down responses. 
Risk 3: Includes OR-based SQL injection tests and other potentially destructive payloads that may modify data or cause havoc in production environments


--level 
option in sqlmap controls the scope of SQL injection testing, determining which parts of an HTTP request are scanned and the number of tests performed.  It accepts integer values from 1 to 5, with 1 being the default and least aggressive setting. 
Impact of Level Values:
------------------------
Level 1 (Default): Tests only GET and POST parameters. 
Level 2: Adds tests for HTTP Cookie header values. 
Level 3: Adds tests for HTTP User-Agent and Referer header values. 
Level 4: Includes all previous tests plus null values and other specific bugs.
Level 5: The highest level, testing all possible injection points (including HTTP Host header) and using a more extensive list of payloads and boundaries. 


--verbosity 
option in sqlmap is controlled by the -v flag and accepts integer values from 0 to 6. This setting determines the amount of detail displayed in the output, allowing users to balance between concise error reporting and detailed debugging information. 
Verbosity Levels
------------------
Level 0: Shows only Python tracebacks, errors, and critical messages. 
Level 1: (Default): Displays information, warnings, errors, critical messages, and tracebacks. 
Level 2: Adds debug messages; recommended for the detection phase. 
Level 3: Adds injected payloads; recommended for debugging or reporting to developers. 
Level 4: Adds HTTP requests to the output. 
Level 5: Adds HTTP response headers.
Level 6: Adds HTTP response page content.


--technique flag in sqlmap specifies which SQL injection methods the tool should attempt.By default, sqlmap tests all six supported techniques in the order BEUSTQ (Boolean-based blind, Error-based, UNION query, Stacked queries, Time-based blind, and Inline/Out-of-band). 
Users can specify a subset of techniques by providing a string of corresponding characters:
B: Boolean-based blind (infers data via true/false conditions)
E: Error-based (leverages verbose DBMS error messages)
U: UNION query (injects UNION SELECT statements)
S: Stacked queries (appends additional statements separated by ;)
T: Time-based blind (relies on delays like SLEEP or WAITFOR)
Q: Inline/Out-of-band (uses functions like LOAD_FILE() or DNS exfiltration)
